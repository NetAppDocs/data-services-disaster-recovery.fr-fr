= Basculez les applications vers un site distant avec NetApp Disaster Recovery
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/use/


[role="lead"]
En cas de catastrophe ou d'événement similaire, utilisez NetApp Disaster Recovery pour récupérer les charges de travail critiques afin que les applications puissent reprendre sur le site de reprise après sinistre avec les mappages prévus.

La reprise après sinistre prend également en charge les tests de basculement. Effectuer ces tests vous aide à vous familiariser avec le processus et confirme que la reprise fonctionne comme vous l’attendez.

*Rôle NetApp Console requis* Le rôle Super admin, Disaster recovery admin ou Disaster recovery failover admin est requis pour effectuer cette tâche. link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-disaster-rec-roles.html["En savoir plus sur les rôles et les autorisations des utilisateurs dans NetApp Disaster Recovery"^]. link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["En savoir plus sur les rôles d'accès à la NetApp Console pour tous les services"^].



[[about-this-task]]
== À propos de cette tâche

Lors du basculement, Disaster Recovery utilise par défaut la copie Snapshot SnapMirror la plus récente, bien que vous puissiez sélectionner un snapshot spécifique à partir d'un snapshot à un point dans le temps (conformément à la politique de rétention de SnapMirror). Utilisez l'option de point dans le temps si les répliques les plus récentes sont compromises, par exemple lors d'une attaque par rançongiciel.

Ce processus diffère selon que le site de production est sain ou non et que vous effectuez un basculement vers le site de reprise après sinistre pour des raisons autres qu'une défaillance critique de l'infrastructure :

* Panne critique d’un site de production où la source vCenter, le cluster Kubernetes ou le cluster ONTAP n’est pas accessible : Disaster Recovery vous permet de sélectionner n’importe quel instantané disponible à partir duquel restaurer.
* L'environnement de production est sain : vous pouvez soit « Prendre un instantané maintenant » ou sélectionner un instantané précédemment créé.


Cette procédure interrompt la relation de réplication, met hors ligne les charges de travail sources, rend les volumes répliqués disponibles sur le site de reprise après incident, redémarre les charges de travail protégées conformément aux règles de basculement définies dans le plan et active la lecture/écriture sur le site cible. Pour les charges de travail VMware, le service met hors ligne les VM sources du vCenter, enregistre les volumes comme datastores dans le vCenter de reprise après incident et redémarre les VM protégées. Les charges de travail Kubernetes suivent une séquence équivalente pour leurs applications et leurs volumes persistants.



[[test-the-failover-process]]
== Tester le processus de basculement

Avant de procéder à un basculement en direct, vous pouvez effectuer un test pour vérifier la préparation. Les charges de travail restent en ligne pendant le processus de test.

Lors d'un test de basculement des charges de travail VMware, Disaster Recovery crée temporairement des machines virtuelles. Disaster Recovery associe un datastore temporaire prenant en charge le volume FlexClone aux hôtes ESXi. Un test de basculement des charges de travail Kubernetes suit une séquence équivalente pour les applications protégées et les volumes persistants sur le cluster de destination.

Ce processus ne consomme pas de capacité physique supplémentaire sur le stockage ONTAP sur site ou sur le stockage FSx pour NetApp ONTAP dans AWS. Le volume source d'origine n'est pas modifié et les tâches de réplication peuvent se poursuivre même pendant une reprise après sinistre.

Une fois le test terminé, il est recommandé de réinitialiser l'environnement de test à l'aide de l'option *Clean up test*.

Une opération de basculement de test n'a _pas_ d'impact sur les charges de travail de production, la relation SnapMirror utilisée sur le site de test et les charges de travail protégées qui doivent continuer à fonctionner normalement.

En cas de basculement de test, Disaster Recovery effectue les opérations suivantes.

* Effectuez des vérifications préalables sur le cluster de destination et la relation SnapMirror .
* Créez un nouveau volume FlexClone à partir du snapshot sélectionné pour chaque volume ONTAP protégé sur le cluster ONTAP du site cible.
* Si des banques de données sont VMFS, créez et mappez un iGroup à chaque LUN.
* Enregistrez les machines virtuelles cibles dans vCenter en tant que nouveaux datastores.
* Mettez sous tension les machines virtuelles cibles en fonction de l'ordre de démarrage indiqué sur la page Groupes de ressources.
* Désactivez toutes les applications de base de données prises en charge dans les machines virtuelles indiquées comme « cohérentes avec les applications ».
* Si les clusters vCenter et ONTAP sources sont toujours actifs, créez une relation SnapMirror en sens inverse pour répliquer toutes les modifications lors de l'état de basculement vers le site source d'origine.


.Étapes
. Connectez-vous à la https://console.netapp.com/["NetApp Console"^] .
. Dans la navigation de gauche de la NetApp Console , sélectionnez *Protection* > *Reprise après sinistre*.
. Dans le menu Disaster Recovery, sélectionnez *Replication plans*.
. Sélectionnez le plan de réplication.
. À droite, sélectionnez l'option *Actions* image:../use/icon-horizontal-dots.png["Icône du menu Actions dans le service de reprise après sinistre"] et sélectionnez *Tester le basculement*.
. Sur la page de test de basculement, choisissez l’instantané pour le test de basculement : sélectionnez **Créer un instantané maintenant** ou **Sélectionner** pour choisir un instantané existant. Si vous choisissez **Sélectionner**, choisissez l’instantané existant.
+
Saisissez ensuite « Test failover » et sélectionnez *Test failover*.

. Une fois le test terminé, nettoyez l’environnement de test.




[[clean-up-the-test-environment-after-a-failover-test]]
== Nettoyer l'environnement de test après un test de basculement

Une fois le test de basculement terminé, vous devez nettoyer l'environnement de test. Ce processus supprime les ressources de test temporaires et les FlexClones de l'emplacement de test. Pour les charges de travail VMware, cela inclut les VM temporaires et les datastores temporaires.

.Étapes
. Dans le menu Disaster Recovery, sélectionnez *Replication plans*.
. Sélectionnez le plan de réplication.
. À droite, sélectionnez l'option *Actions* image:../use/icon-horizontal-dots.png["Icône du menu Actions dans le service de reprise après sinistre"] puis *Nettoyer le test de basculement*.
. Sur la page de test de basculement, saisissez « Nettoyage du basculement », puis sélectionnez *Test de nettoyage du basculement*.




[[fail-over-the-source-site-to-a-disaster-recovery-site]]
== Basculer le site source vers un site de reprise après sinistre

En cas de sinistre, basculez votre site principal vers le site de reprise d'activité à la demande. Pour les charges de travail VMware, vous pouvez basculer votre site VMware principal sur site vers un autre site VMware sur site ou vers VMware Cloud on AWS avec FSx for NetApp ONTAP. Pour les charges de travail Kubernetes, vous basculez vers le cluster de destination dans le plan de réplication.

Le processus de basculement comprend les opérations suivantes. Les opérations faisant référence à vCenter, aux machines virtuelles ou aux banques de données s'appliquent aux charges de travail VMware ; les charges de travail Kubernetes suivent les opérations équivalentes pour leurs applications et volumes persistants :

* Disaster Recovery effectue des vérifications préalables sur le cluster de destination et la relation SnapMirror .
* Si vous avez sélectionné le dernier instantané, la mise à jour de SnapMirror est effectuée pour répliquer les dernières modifications.
* Les machines virtuelles sources sont hors tension.
* La relation SnapMirror est rompue et le volume cible est rendu accessible en lecture/écriture.
* En fonction de la sélection de l'instantané, le système de fichiers actif est restauré sur l'instantané spécifié (le plus récent ou sélectionné).
* Les banques de données sont créées et montées sur le cluster ou l’hôte VMware ou VMC en fonction des informations capturées dans le plan de réplication.  Si des banques de données sont VMFS, créez et mappez un iGroup à chaque LUN.
* Les machines virtuelles cibles sont enregistrées dans vCenter en tant que nouveaux datastores.
* Les machines virtuelles cibles sont mises sous tension en fonction de l'ordre de démarrage indiqué sur la page Groupes de ressources.
* Si la source vCenter est toujours active, mettez hors tension toutes les machines virtuelles côté source qui font l'objet d'un basculement.
* Désactivez toutes les applications de base de données prises en charge dans les machines virtuelles indiquées comme « cohérentes avec les applications ».
* Si les clusters source vCenter et ONTAP sont toujours actifs, créez une relation SnapMirror en sens inverse pour répliquer les modifications apportées pendant l’état de basculement vers le site source d’origine. La relation SnapMirror est inversée, de la machine virtuelle cible vers la machine virtuelle source.



TIP: Pour les workloads VMware, une fois le basculement démarré, vous pouvez voir les VM récupérées dans le vCenter du site de reprise après sinistre (VM, réseaux et datastores). Par défaut, les VM sont récupérées dans le dossier Workload.

.vCenter
--
Pour les plans de réplication basés sur un datastore, si vous avez ajouté et découvert des machines virtuelles mais n'avez pas fourni de détails de mappage, ces machines virtuelles sont incluses dans le basculement. Le basculement échouera et une notification sera affichée dans les tâches. Vous devez fournir les détails de mappage pour que le basculement réussisse.

.Étapes
. Dans le menu Disaster Recovery, sélectionnez *Replication plans*.
. Dans le menu déroulant, filtrez sur les plans de réplication *vCenter*.
+
image::site-type-toggle.png[Capture d'écran du bouton de basculement du type de site]

. Sélectionnez le plan de réplication.
. À droite, sélectionnez l'option *Actions* image:../use/icon-horizontal-dots.png["Icône du menu Actions dans le service de reprise après sinistre"], survolez *Récupérer* puis sélectionnez *Basculement*.
+
image:dr-plan-failover3.png["Page de basculement"]

. Choisissez la copie instantanée que vous souhaitez utiliser pour le basculement :
+
** Choisissez *Prendre un instantané maintenant* pour créer un tout nouvel instantané qui sera copié sur le cluster de destination avant le basculement.
** Choisissez *Utiliser le dernier instantané* pour utiliser l'instantané le plus récent disponible sur le cluster de destination.
** Choisissez *Sélectionner* pour consulter une liste de snapshots triés par date de création.
+

NOTE: Lors de la sélection d'une ligne de base de snapshot spécifique, les snapshots de transfert SnapMirror sont masqués par défaut car ils peuvent être supprimés en cours de basculement. Cette suppression entraîne l'impossibilité de reprotéger la charge de travail après le basculement en raison d'une erreur « aucun snapshot commun trouvé ». Vous pouvez toujours utiliser les snapshots de transfert SnapMirror, mais vous devrez effectuer une confirmation supplémentaire pour reconnaître le risque.



. Sélectionnez *Forcer le basculement* si vous souhaitez que le basculement se poursuive même lorsque le service détecte une erreur qui le bloquerait normalement.
. Sélectionnez *Ignorer la protection* si vous souhaitez que le service ne crée pas automatiquement de relation de protection inverse SnapMirror après un basculement du plan de réplication. Cette option est utile si vous souhaitez effectuer des opérations supplémentaires sur le site restauré avant de le remettre en ligne dans Disaster Recovery.
+

TIP: Vous pouvez établir une protection inverse en sélectionnant *Protéger les ressources* dans le menu Actions du plan de réplication.  Cela tente de créer une relation de réplication inverse pour chaque volume du plan.  Vous pouvez exécuter cette tâche à plusieurs reprises jusqu'à ce que la protection soit restaurée.  Une fois la protection restaurée, vous pouvez lancer une restauration automatique de la manière habituelle.

. Tapez « failover » dans la case.
. Sélectionnez *Fail over*.
. Pour vérifier la progression, dans le menu, sélectionnez *Suivi des tâches*.
